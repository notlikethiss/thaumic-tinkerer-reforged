# Чеклист проверки полноты порта Thaumic Tinkerer

Цель: подтвердить соответствие Thaumic Tinkerer 2.5 из ветки `1.7-final` в пределах согласованного состава порта. Успешная сборка, наличие предмета в Creative и зелёные GameTests по отдельности не подтверждают полноту порта.

Отмечай пункт только после выполнения сценария. Для ошибки записывай шаги, ожидаемый результат по оригиналу, фактический результат, версии, лог и при необходимости скриншот. Непроверенный пункт остаётся пустым. Неприменимые пункты помечай `N/A` с причиной.

- [ ] Сохранить точную копию исходников оригинала в `reference/tt-src`. Инструмент `tools/fetch_tt.py` получает ветку `1.7-final`; зафиксировать также commit исходной ветки либо контрольную сумму скачанного архива, чтобы эталон не менялся между проверками.
- [ ] Подготовить отдельные тестовые миры: Creative для изолированных сценариев и Survival для прохождения прогрессии. Для серверной проверки нужны выделенный сервер и два клиента.
- [ ] Подготовить эталонную установку Minecraft 1.7.10 с соответствующей версией TT 2.5 и Thaumcraft. Сравнивать одинаковые сценарии; для сложных случаев сверяться с исходниками оригинала.
- [ ] Согласовать отклонения от оригинала в таблице ниже. Отсутствие нужного API в новой версии само по себе не означает, что игровая функция может быть пропущена.

## 2. Автоматические проверки

Из рабочей копии `mc/1.21.1`: Gradle на Java 25, тулчейн Java 21. Автоматические результаты для этой ветки в `BACKPORT_VALIDATION.md`; пункты ниже не отмечаются без выполнения соответствующего сценария.

```sh
python3 tools/check_seams.py
python3 tools/inventory.py --check --strict --all
./gradlew build
./gradlew runGameTestServer
```

GameTestServer запускай с отдельной тестовой папкой игры либо после сохранения нужных данных из `run/`. Обычная задача `build` не запускает игровые GameTests.

- [ ] `check_seams.py` завершается без нарушений границ API.
- [ ] `inventory.py --check --strict --all` показывает `check: ok`, а для `registered`, `models`, `lang` нет пропусков. Каталог оригинала присутствует: сообщение о пропущенной проверке исходного языка недопустимо для полной сверки.
- [ ] `build` завершается успешно; полученный JAR устанавливается в обычный игровой профиль.
- [ ] GameTestServer действительно выполняет тесты пространства `thaumictinkerer`, завершает их без ошибок и пропусков. Сохранить итоговый лог и число выполненных тестов.
- [ ] В результатах есть все подсистемы из `Features.tests()`, базовые тесты и smoke-тесты. Особенно проверить `research_table_research_matches_tt_table` и `research_table_research_pages_resolve`.
- [ ] Повторить игровые тесты после исправления найденных ошибок; нестабильный тест считать проблемой до выяснения причины.

Снимок структуры на момент составления чеклиста: в карте контента 33 уникальных блока и 114 предметов; в таблицах 74 исследования и 129 записей рецептов оригинала, включая записи исключённого контента и варианты. В исходниках зарегистрированы 225 случаев через `TtGameTestSuite.add` и 2 smoke-теста. Это ориентиры для проверки состава, а не результат выполнения игровых тестов.

Во время составления документа `inventory --strict` и `check_seams` прошли. Ручные пункты ниже и полный запуск GameTests этим документом не подтверждаются.

- [ ] Сверить `tools/tt_recipes.json` с оригиналом: все активные варианты присутствуют, ингредиенты разрешены, отсутствуют неразобранные значения `?`.
- [ ] Для каждого рецепта проверить тип крафта, форму и зеркальность, ингредиенты и их допустимые варианты, количество результата, данные предмета, исследование, vis/эссенцию и нестабильность инфузии.

- [ ] Сверить разрешённые замены старых metadata-предметов, ore dictionary и новых тегов. Каждая игровая разница должна быть объяснена в таблице отклонений.

Для повторного извлечения эталонных таблиц существуют команды:

```sh
python3 tools/extract_tt_research.py
python3 tools/extract_tt_recipes.py
```

Они перезаписывают соответствующие JSON-файлы. Перед использованием зафиксируй эталон, после проверь diff. Изменение таблицы ради прохождения теста не доказывает исправление порта.

`extract_tt_recipes.py --compare /absolute/path/to/runtime-recipes.json` умеет сравнивать таблицу с дампом рецептов, зарегистрированных во время игры. Сам дамп эта команда не создаёт: нужен файл в формате, который читает `tools/compare_recipes.py`. В текущих проверенных исходниках готовая игровая команда экспорта не найдена. Если использовать этот путь, сначала подготовить экспорт, затем разобрать все `PROBLEMS`, `SOFT` и `ADDON ONLY`; один код завершения скрипта не подтверждает отсутствие расхождений.

## 4. Общие проверки для каждого объекта

Эти пункты применяются к каждому активному блоку и предмету из карты, включая варианты с данными.

- [ ] Есть корректное имя, модель, текстура, иконка, описание и нужная запись в Thaumonomicon на `en_us` и `ru_ru`. Ключи перевода, пустые страницы и missing texture отсутствуют.
- [ ] Объект можно получить предусмотренным способом в Survival. Все ингредиенты доступны без команд и предметов исключённого контента.
- [ ] Повороты, размещение, размеры стака, прочность, редкость, инструмент для добычи и дроп соответствуют эталону либо записанным отклонениям.
- [ ] Основное действие, Shift-действие, переключение режима и действие без нужного ресурса работают ожидаемо. Неиспользуемые кнопки ничего не расходуют.
- [ ] При ломании блока содержимое и сам блок выпадают ровно один раз. Creative не маскирует потерю или дублирование предметов.
- [ ] Данные предмета сохраняются при перекладывании, выбрасывании, подборе, хранении в сундуке и передаче второму игроку.
- [ ] Состояние блока и содержимое сохраняются после выхода из мира, перезапуска сервера и выгрузки/загрузки чанка.
- [ ] Другой игрок видит правильное состояние, анимацию, эффекты и изменения инвентаря. Нет действий, произошедших только на клиенте.
- [ ] Недопустимая цель, пустой источник, полный приёмник и недостаток ресурсов обрабатываются без потерь, дюпов и зависания.

- [ ] Посадка создаёт нужную грядку и растение. Проверить исходный блок почвы, освещение, стадии роста и действие стихийной мотыги.
- [ ] Незрелое и зрелое растения дают правильные семена/зерно; аспект не теряется при сборе и повторной посадке.
- [ ] Проверить мутации, влияние соседей, tendency, обмен tendency и предел накопления residue по оригиналу, включая аспекты вне четырёх базовых видов зерна.
- [ ] Проверить особый лут для каждого поддерживаемого аспекта. Случайные результаты сравнивать серией повторений, фиксируя число попыток и частоты.
- [ ] Костная мука работает согласно настройке; растение, грядка и их данные сохраняются после перезагрузки чанка.

## 10. Снаряжение и некромантия

- [ ] XP Talisman: поглощение и возврат опыта, предел хранения, переключение режима, отсутствие копирования опыта при смерти и передаче предмета.
- [ ] Blood Sword: урон, бонусы движения, ответный удар и получение аспектов душ соответствуют оригиналу.
- [ ] Revealing Helm: броня и функции очков откровения работают одновременно.
- [ ] Infused Inkwell: используется как инструмент записи, расходуется, пополняется по рецепту и не даёт бесконечный ресурс.
- [ ] Tome of Knowledge Sharing: записать знания одного игрока и передать второму; проверить стоимость, ограничения Survival, сохранение данных и отсутствие непредусмотренного открытия KAMI.
- [ ] Получить 17 видов аспектов душ от предусмотренных существ; отдельно проверить условия и случайность выпадения.
- [ ] Изготовить condensed и infused варианты всех аспектов душ; варианты не смешиваются и сохраняются в инвентаре.
- [ ] Necromancy Tablet: проверить все комбинации из таблицы призыва, появление нужного существа и расход душ/эссенции.
- [ ] Неизвестная комбинация не призывает случайного моба; редстоун останавливает работу по эталону; infused-души ведут себя согласно своему правилу сохранения.
- [ ] Перезапуск и удаление планшета во время призыва не копируют существ и содержимое.

## 11. KAMI

### Материалы и обычное снаряжение

- [ ] Проверить выпадение Nether Shard и Ender Shard в нужных измерениях и при нужных условиях; отдельно проверить шанс выпадения серией попыток.
- [ ] Получить Ichor, Ichor Cloth, Ichorium Ingot и Nugget; проверить обратимые преобразования и количество материала.
- [ ] Ichorcloth Rod и Ichorium Cap собираются в рабочую палочку с правильной ёмкостью и свойствами.
- [ ] Обычные ихориевые кирка, лопата, топор и меч имеют правильные характеристики, зачарования и неразрушимость.
- [ ] Четыре части обычной ихорной брони имеют правильную защиту и скидку vis; проверить отдельные части и полный комплект.

### Пробуждённые инструменты

- [ ] У каждого инструмента переключаются и сохраняются все три режима; название и визуальная индикация соответствуют выбранному режиму.
- [ ] Кирка: Block, Square и Line; проверить каждую грань, ориентацию области и пределы разрушения.
- [ ] Лопата: Block, Square и Column; проверить границу мира, смешанные материалы и жидкость возле области.
- [ ] Топор: Block, Square и Tree; проверить обычное и большое дерево, соседнюю постройку и предел обработки.
- [ ] Меч: Single, Area и Soul; проверить выбор целей, урон, накопление и расход soul hearts.
- [ ] Массовая добыча сохраняет ожидаемые дропы и взаимодействие с зачарованиями, не обходит запрет разрушения и не затрагивает недопустимые блоки.
- [ ] Soul hearts правильно поглощают урон; смерть, повторный вход и смена измерения не создают бесконечную защиту.

### Пробуждённая броня

- [ ] Cowl of the Abyssal Depths: подводное дыхание/зрение, поведение в лаве, восстановление здоровья и функции шлема сверены с оригиналом.
- [ ] Robes of the Stratosphere: полёт и защита от снарядов работают; снятие или отключение брони корректно убирает предоставленный полёт в Survival.
- [ ] Leggings of the Burning Mantle: огнестойкость и создаваемое освещение работают, служебный свет не накапливается бесконечно.
- [ ] Boots of the Horizontal Shield: скорость, управление в воздухе, шаг, прыжок, ускорение добычи, падение и взаимодействие с землёй сверены с оригиналом.
- [ ] Клавиша отключения брони (по умолчанию `U`) и отключение отдельных частей работают и синхронизируются с сервером.
- [ ] Снятие/отключение комплекта не удаляет чужие эффекты и полёт Creative/Spectator; повторное надевание не складывает бонусы бесконечно.
- [ ] Модели брони, крылья и анимации правильно видны от первого/третьего лица и второму игроку.

### Артефакты KAMI

- [ ] Black Hole Talisman (`block_talisman`): выбрать блок, поглощать, размещать, выдавать стек и наполнять контейнер; проверить счётчик, предел хранения и переключение.
- [ ] Worldshaper's Looking Glass (`placement_mirror`): выбор блока, размеры и ориентация области, предварительный просмотр, корректный расход; нехватка блоков не создаёт бесплатную постройку.
- [ ] Ichor Pouch: хранение предметов, Shift-клики, ограничения содержимого и поиск фокусов переключателем палочки; проверить попытку вложения сумки в саму себя.
- [ ] Cat Amulet: предусмотренный слот, поведение криперов и других мобов в радиусе, прекращение эффекта после снятия.
- [ ] Protoclay: выбор подходящего инструмента при ударе по разным блокам; нет копирования, потери данных или бесконечной смены слота.

### Warp Gate и Sky Pearl

- [ ] Создать и привязать Sky Pearl; название, место назначения и данные сохраняются после передачи другому игроку.
- [ ] Установить жемчужины в Warp Gate, проверить допустимые слоты, список направлений и переход к нужной цели.
- [ ] Проверить работу между измерениями, занятый выход, удалённую цель, выгруженный чанк, блокировку ворот и право использования.
- [ ] Удаление ворот возвращает установленные жемчужины ровно один раз; сохранение мира не сбрасывает привязки.
- [ ] Два игрока одновременно используют ворота без подмены назначения, потери предметов и рассинхронизации.

## 12. Выделенный сервер, настройки и совместимость

- [ ] Установить релизные JAR аддона, Thaumcraft и обязательных зависимостей в чистый клиент и выделенный сервер. Запускать также без JEI.
- [ ] Сервер без графического окружения запускается, сохраняет мир и перезапускается без ошибок загрузки клиентских классов.
- [ ] Повторить на двух клиентах ключевые сценарии: GUI механизмов, камуфляж, фокусы, перемещение сундука, полёт, обмен знаниями и Warp Gate.
- [ ] Проверить одновременную работу с одним GUI, Shift-клики, быстрые повторные нажатия и закрытие окна во время операции. Итоговые предметы и ресурсы должны совпадать на сервере и обоих клиентах.
- [ ] С установленным JEI проверить отображение предусмотренных рецептов и ингредиентов; отсутствие JEI не должно мешать загрузке и основным механикам.
- [ ] Проверить каждую настройку в обоих состояниях: `general.kami.forceenabled`, `general.imbuedFire.enabled`, `general.imbuedFire.cake.enabled`, `general.shareTome.survival.enabled`, `general.cropsAllowBonemeal.enabled`, `general.modFlight.enabled`, `general.placementMirror.blocks.show`, `general.tooltipIndicators.enabled`.
- [ ] Клиенты получают серверные значения синхронизируемых настроек; локальная настройка клиента не обходит ограничения сервера.
- [ ] На уровне сетевого кода проверить отклонение запросов из чужого/закрытого GUI, слишком далёкого блока, неверного слота и выдуманного назначения телепортации. Это отдельная проверка кода или автоматический тест, не обычный игровой клик.
- [ ] После смерти, повторного входа, перехода между измерениями и перезапуска сохраняются предусмотренные данные; снятые бонусы не остаются навсегда.

## 13. Стабильность и финальная приёмка

- [ ] Задать и записать нагрузку: число механизмов, растений, аттракторов, областей газа и источников огня. Провести длительный прогон с сохранениями и перезапусками.
- [ ] Сравнить TPS/MSPT сервера и FPS клиента до и после нагрузки. Заранее записать приемлемые пределы для конкретной машины; проверить, что нагрузка не растёт после выключения/удаления механизмов.
- [ ] Проверить `latest.log` клиента и сервера: нет повторяющихся исключений, отсутствующих рецептов/текстур, ошибок сериализации и сетевых сообщений.
- [ ] Все обязательные пункты отмечены, все `N/A` обоснованы, отличия от оригинала согласованы, открытых блокирующих ошибок нет.
- [ ] Финальный JAR соответствует проверенному commit. Пройти хотя бы короткий повторный прогон именно установленного JAR вне среды разработки.
- [ ] Сохранить отчёт: версии и commit, конфигурация, результаты скриптов и GameTests, миры/сценарии ручной проверки, список отличий и найденных дефектов.
