# Проверки бэкпорта 1.21.1

## Исправление CI от 2026-10-19

Первоначальная локальная проверка использовала готовый кеш ванильных реестров. На чистом Linux runner генерация отчётов запускала Java по жёстко заданному пути Homebrew и падала до этапа компиляции. Эта проверка чистого окружения была пропущена в исходной приёмке.

В базе исправлено определение Java: версия из переменных CI `JAVA_HOME_<version>_*`, затем `JAVA_HOME` и `PATH`, с проверкой минимальной версии и понятной ошибкой при отсутствии подходящего JDK. Коммит базы: `9d274e3d7bba7e4d60d371b555d694fd70936bc2`; его нужно включить в `mc/1.21.1` базы перед повторным запуском workflow аддона. Workflow запускает тесты валидатора базы до проверки ресурсов.

Все 12 тестов валидатора прошли. Дополнительно выполнен настоящий ванильный datagen 1.21.1 на JDK 21 в отдельном пустом каталоге: готовые отчёты отсутствовали, использовались только кешированные исходные JAR Minecraft. Новый отчёт registries.json создан, полная проверка ресурсов аддона дала 0 проблем. Linux-пути и выбор JDK GitHub Actions проверены регрессионными тестами; сам GitHub Actions из этой сессии не запускался. Игровые классы и ресурсы данным исправлением не меняются; результаты исходной игровой проверки ниже относятся к первоначальному бэкпорту.

Дата: 2026-10-18. Ветка аддона `mc/1.21.1`, отдельная рабочая копия `.worktrees/mc-1.21.1`. Перенесены все существующие модули, включая KAMI. Автоматические проверки пройдены; полная игровая и визуальная приёмка остаётся открытой.

## Результаты сверки оригинала

Эталонные таблицы исследований и обычных рецептов не подгонялись под реализацию. Три неразрешённых рецепта исходного извлечения — `ASPECT_ANALYZER`, `GOLEM_CONNECTOR`, `REMOTE_PLACER` — входят в согласованные исключения. Матрица и границы покрытия приведены в `BACKPORT_AUDIT.md` и `tools/backport/audit.json`.

Десять информационных отличий сравнения обычных рецептов:

- Два слота `MOB_MAGNET`: оригинальный `RecipeHelper.oreDictOrStack` выбирает медь при наличии ore dictionary; золотой fallback в 1.21.1 не нужен.
- Шесть результатов `INFUSED_POTIONS0..5`: metadata аспекта представлена компонентом `seed_aspect`; его значения проверяются явно.
- Два компонента `ICHOR`: в исходной декларации x8, но `InfusionRecipe.areItemStacksEqual` TC4 не проверяет размер стека, а `TilePedestal.getInventoryStackLimit()` возвращает 1. Порт сохраняет фактическое требование одного осколка каждого вида и результат x8. Сырые исходные количества остаются в таблице. GameTest проверяет подбор и отказ при отсутствующем осколке.

Подтверждённые исправления поведения относительно исходной ветки порта:

- Tree сохраняет pickup delay и прибавляет 20 к счётчику тиков собранных дропов, как TT. Снятие задержки удалено; добавлена регрессия.
- Восемь старших зачарований станка требуют `TTENCH_VAMPIRISM`, как в оригинале, вместо ошибочного требования отдельного исследования. Доступность и реальное применение зачарования проверяются GameTests; независимый runtime-сравнитель проверяет всю таблицу.
- Существующий сбор дропов массовой добычи закреплён дополнительным тестом. Это проверка уже имевшегося поведения, а не новое исправление.
- Неиспользуемый параметр типа блока в оригинальном `removeBlocksInIteration` сохранён как особенность: Column не останавливается на промежуточном камне и добывает подходящие лопате материалы.

Версионные исправления включают отложенное применение свойств регистрации, сохранение содержимого при удалении механизма, ненулевую позицию уведомления Transvector, динамические item/fluid capabilities, синхронизацию вложений и JEI subtype семян. Подробности API — в `BACKPORT.md`.

## Сервер и клиент

Обычный выделенный сервер стартовал без JEI, создал отдельный мир `backport-validation`, выполнил `/reload`, сохранился и перезапустился. Затем сервер запущен с окончательными JAR обоих модов: в classpath нет каталогов классов/ресурсов аддона. Использовался dev-launcher NeoForge, а не установленный через installer серверный профиль. Полная установка в пользовательский игровой профиль остаётся ручным пунктом.

После перезапуска прочитаны данные пяти механизмов: Thaumic Restorer с киркой и damage 42, Dynamism Tablet с мечом, закрытый Warp Gate с координатами Sky Pearl, Corporeal Attractor с soul mould зомби и adult-флагом, Transvector Interface с камуфляжем oak planks. Проверены идентификаторы, количества, компоненты и настройки. `/reload`, `save-all flush` и штатная остановка прошли. Свидетельства — `validation/persistence.json` и логи в комплекте артефактов.

Клиент отдельно загрузился с JEI и без JEI и подключился к тестовому серверу. На сервере экипирован полный пробуждённый комплект брони и выданы предметы для загрузки специальных моделей; рядом размещены механизмы с камуфляжем. JEI зарегистрировал категории базы и рецепты аддона; предупреждение о схлопывании вариантов семян устранено subtype-интерпретатором. Эти запуски проверяют загрузку ресурсов и классов; качество изображения, анимаций и GUI визуально не подтверждено.

В логах остаются предупреждения о трёх blockstate-моделях полей namespace `thaumcraft`, mipmap/shader uniforms базы, 160 дубликатах рецептов JEI базы и dev-refmap зависимостей. При первоначальной генерации мира встречались предупреждения верхнего блока eldritch obelisk базы. Ограничение окружения вызывает `LanServerPinger: No route to host`. Принудительное завершение тестовых клиентов оставило серверные `SocketException: Connection reset`; штатный серверный запуск и остановка не завершались падением. Эти сообщения не скрыты и не считаются исправленными данным бэкпортом.

## Открытая ручная приёмка

Проверки выполнять в отдельных мирах 1.21.1. Миграция миров с 26.3 не входит в задачу. Полный чеклист — `PORTING_CHECKLIST.md`. Минимальные конкретные сценарии:

1. Установить оба итоговых JAR, TerraBlender и Curios в чистый профиль NeoForge 21.1.256 на Java 21. Запустить клиент с JEI и без него; проверить F3+T, Creative, Thaumonomicon, все экраны, броню, крылья и модели режимов инструментов. Сравнить с исходными ассетами и TT.
2. Двумя клиентами открыть один механизм. Выполнить Shift-клики, смену слотов, быстрое закрытие GUI, разрушение и перенос заполненного контейнера. Сумма предметов до и после должна сохраняться, кроме предусмотренного расхода.
3. Через Transvector передать 32 одинаковых предмета и 1000 mB жидкости; проверить каждую сторону доступа. Перепривязать цель, выгрузить и загрузить её чанк, затем удалить цель. Считать суммарные ресурсы у источника и назначения; повторить с другим клиентом рядом.
4. Проверить души и бонусы брони после входа, смерти, возрождения, смены измерения и повторного подключения. Оба клиента должны видеть полёт/крылья, владелец — свои данные душ; снятие брони и отключение серверного modFlight должны убирать соответствующий бонус.
5. Использовать каждый фокус, планшет, массовые режимы инструментов, душепризыв, растения и Warp Gate в Survival. Проверить расход vis/эссенции/XP, запрет действий без прав, сохранение назначения и отсутствие потерянных предметов. Отдельно проверить конфиги и выключенный KAMI.
6. На станке с одним исследованным Vampirism проверить доступность восьми старших зачарований и недоступность младших без их исследования. Сверить стоимость уровней с таблицей TT. Проверить Spellbinding Cloth и Tome of Knowledge Sharing между двумя игроками.
7. После длительной совместной игры выполнить `/reload`, сохранение и перезапуск. Снять TPS/MSPT/FPS до нагрузки, под нагрузкой и после удаления механизмов. Зафиксировать результаты и ошибки с шагами воспроизведения.

Эти пункты, полное Survival-прохождение, визуальная сверка, двухклиентская синхронизация и нагрузочные измерения не отмечены выполненными. Полная приёмка до их завершения не подтверждается.
